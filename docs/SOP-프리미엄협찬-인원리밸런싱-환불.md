# SOP — 프리미엄 협찬 인원 리밸런싱 & 예수금 환불 처리 (최종)

> 작성 2026-07-06 · 대상 그로쓰팀 · 데이터 Airtable `캠지기 모집 폼`
> ⚠️ **돈(예수금·정산) 다루는 절차다. §2 절대 규칙을 어기면 기존 신청자 정산이 붕괴한다.**

---

## 0. 목적 & 적용 범위
- **목적**: 미모집(안 채워진) 협찬 자리를 ① 모집 잘 되는 구성으로 **전환**, ② 기한 연장으로 **재활성**, ③ 안 되면 **환불** — 캠핑장이 협찬 홍보를 끝까지 받고 예수금 정산을 정확히 맞춘다.
- **적용**: 프리미엄 협찬(`캠지기 모집 폼`) 캠페인 중 미모집 자리가 있는 건.
- **지향**: 캐시 환불 최소화 · 예수금을 "일하는 돈"으로 유지 · **정산 안전 최우선**.

---

## 1. 핵심 원칙
1. **환불 최소화** — 미모집 자리를 판매 가능한 구성으로 돌려 환불 차액을 최소화.
2. **이벤트 기준 계산** — 이벤트 캠페인은 그 캠페인의 이벤트 단가로. (인원만 바꾸면 자기 단가·VAT로 자동 재계산)
3. **기한 연장** — 신규 전환·재모집 인원은 콘텐츠 제작 기한을 **확정 주시는 날로부터 2개월** 연장.
4. **정산 안전 최우선** — §2 절대 규칙 준수.

---

## 2. 🚨 절대 규칙 — 정산 꼬임 방지 (최우선)
등급별 단가는 Airtable에 **필드가 등급당 딱 1개**뿐이고, **이미 매칭된 크리에이터 지급액이 이 필드에서 파생**된다.

1. **매칭 ≥1명이거나 모집 중인 등급의 단가는 절대 변경 금지. 인원 수만 조정.**
2. **신규 자리는 그 등급의 기존 단가를 그대로 상속** (신규에만 다른 금액 = 구조상 불가능).
3. **단가 신규 설정·변경은 매칭 0명인 등급에만** 허용. (전량 미매칭 캠은 현재 기준가로 **재조정** 가능 — 지역·시세 반영. 매칭 1건이라도 있으면 그 등급 단가 변경 금지)

> ❌ 파트너 12만×2명 매칭 상태에서 단가 바꿔 2명 더 모집 → **기존 2명 지급액까지 바뀜 = 정산 붕괴.**
> ✅ 파트너 2명(@12만) 유지 + 라이징 미모집을 **같은 12만짜리 파트너로 추가** → 기존자 불변.

## 4. 금액 계산 모델
```
실입금(예수금) = ( 아이콘단가×인원 + 파트너단가×인원 + 라이징단가×인원 ) × VAT배수
VAT배수 = 프렌들리 → 1.0  /  그 외 → 1.1
환불 = 기존 실입금 − 변경 후 실입금
```
- 단가 = 등급별 **`크리에이터 협찬 제안 금액`(gross)**. (이모지 `🔥/✔️/⭐️`는 수수료 뺀 net — 계산에 쓰지 말 것)
- **반드시 대조**: `실입금 필요 금액`(공식값) = **실제 입금액(구글시트/입금기록)** 인지 확인 후 진행. 안 맞으면 멈추고 확인.
- **단가 필드는 수동이라 맹신 금지** — 안 쓰는 등급은 0으로 비어있기도, 인원 0인데 단가만 남기도.

**워크드 예시 (산과별)**: 기존 파트너2(@120k)+라이징4(@70k) = `(240k+280k)×1.1 = 572,000`. 전환 라이징4→파트너2(120k 유지) = `(120k×4)×1.1 = 528,000`. **환불 44,000.**

## 5. 단가 유추표 (⚠️ "빈 등급" 신규 전환 시에만)
빈 등급(매칭 0)에 신규 단가를 넣을 때만 사용. **매칭 있는 등급은 유추 금지 — 필드값 그대로.**

**판정 우선순위: ① `이벤트 할인` 체크 → ② Created 시점(라이징) → ③ `선택플랜`(프리미엄 상향).**
> 초창기 = 이벤트 도입 전이라 전부 이벤트 미체크 → 이벤트 플래그가 그 시절까지 커버. 라이징 값이 트랙 간 안 겹쳐(비이벤트 5만 ↔ 이벤트 7~8만) 구분 깨끗.

| 트랙 | 라이징 | 파트너 | 아이콘 |
|---|---|---|---|
| 이벤트 O · 일반 (~2026-05-30) | 70,000 | 120,000 | 250,000 |
| 이벤트 O · 일반 (2026-06초~) | **80,000** | 120,000 | 250,000 |
| 이벤트 O · 프렌들리 (VAT·수수료 X) | 70,000 | 110,000 | 240,000 |
| 이벤트 X · 일반 = base (초창기~현재 불변) | 50,000 | 100,000 | 150,000 |

> ⚠️ **프리미엄 플랜 예외** — `선택플랜`이 올인원/대박 아이콘 등이면 비이벤트라도 상향(딥포레스트 아이콘 300k·수타사 라이징 100k·굼벵이 라이징 100k). 아이콘/프리미엄·비표준은 반영 전 확인.

## 6. 판단 로직 — 어떤 조치로 갈까

**리밸런싱(전환)이 성립하려면 2가지가 필요하다:**
1. **시간** — 새 크리에이터를 모집·촬영할 기한이 있나 (없으면 기한 연장으로 확보)
2. **수요** — 몰아줄 "팔리는 등급"이 있나 (뭐라도 신청이 찼나)

```
미모집 발견
├─ 매칭된(팔리는) 등급 있음?
│   ├─ 있음 → 안 팔리는 등급을 팔리는 등급으로 [전환]  (§7-1)
│   │         · 마감 지났으면 → 기한 연장 걸고 전환
│   └─ 없음(0 신청)
│       ├─ 살릴 여지 있음(지역/시세/노출 문제) → [기한 연장 재활성] or [단가 재조정 재구성]  (§7-2)
│       └─ 수요 자체 없음(아이콘 단독 등) → [전액 환불]  (§7-3)
└─ 남은 게 소액 1자리뿐 & 마감 지남 → 실익 없으면 [소액 환불], 팔리는 tier면 [기한 연장]
```

- **전환 방향은 "수요"가 정한다**: 안 팔린 등급(저가든 고가든)을 → 실제 팔리는 등급으로 몬다. (예: 파트너가 안 팔리고 라이징이 팔리면 파트너→라이징)
- **마감 지남 = 무조건 환불 아님**: 예산중립 전환·재모집 여지 있으면 기한 연장(확정일+2개월)으로 되살린다.
- **환불 최소화**: 전환 인원은 예산 내 최대로. 예산 초과(추가입금) 구성은 금지.

## 8. 처리 절차 (Step-by-step)
1. **조회** — 캠핑장 이름으로 해당 레코드만.
2. **현황 파악** — 등급별 목표/신청/미모집 + **매칭된 등급·단가 식별**.
3. **금액 대조** — `실입금 필요 금액` = 실제 입금액?
4. **판단** — §6 로직으로 전환/연장/환불 결정.
5. **설계·검산** — §2 준수(매칭 등급 단가 불변, 빈 등급만 신규설정), 예산 내 최대, 기존/변경후·환불 재계산.
6. **캠지기 카톡** — §9-1(전환) / §9-2(기한연장) / §9-3(환불). 별표 등급·현행/변경·긍정 프레이밍(§10).
7. **회신 수령** — 방향 + (환불건) 계좌.
8. **슬랙** — 환불건만. §9-4 양식으로 **본인 DM 초안** + 하단(B) 검증·반영 → 검토 후 c-staff에 (A)만 게시.
9. **Airtable 반영 (담당자 직접 입력, AI 반영 X)** — (B)/노션 목록대로: 모집 인원 · (빈 등급)단가 · `추가 기간 연장` · `환불 요청 금액`. `실입금`은 자동. **매칭 등급 인원·단가 불변.**
10. **후속** — 구글시트 기재, 통장사본 슬랙 스레드 유첨. (프렌들리는 정산시트만)

## 10. 카톡 작성 규칙 (프레이밍)
- **등급 = 별 개수**: ⭐⭐⭐ 아이콘 / ⭐⭐ 파트너 / ⭐ 라이징.
- **구성은 "현행 / 변경" 블록**으로 분리(한 줄 화살표 X).
- **기한 연장 문구 = "확정 주시는 날로부터 2개월"** (고정일 X).
- **대시보드 링크는 한 줄 단독** 배치(카톡 자동 링크). `https://creative-cocada-bfa5aa.netlify.app/dashboard/login`
- **환불 유도 톤 지양** — 전환/유지를 메인, 환불은 하단 안심 문구로만.
- **마감 지난 건**: "모집이 멈췄다 / 기한 지났다 / 재모집"류 **금지**(반발 유발) → "더 확실히 채워드리려 기한 연장" **선제·긍정** 프레이밍. 남은 자리는 "모집 중".
- **환불 0**: "입금액 변동 없음 — 구성만 조정" + 계좌 문단 삭제, "동의 여부만 회신".
- **프렌들리**: "VAT 포함" 문구 제거.

## 12. 오답노트 (주의)
