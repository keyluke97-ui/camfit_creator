## 0. 정산 주기 & 기준

| 항목 | 값 |
|---|---|
| 정산 대상 | **전월 1일~말일에 "콘텐츠 저장"된 건** |
| 지급일 | **익월 10일** |
| 기준 날짜 필드 | 콘텐츠 업로드 테이블의 **`Created`** (= 시트의 `콘텐츠 저장일`) |

### 🚨 `Created` vs `업로드 날짜` 혼동 금지
두 필드는 다르고, **정산 기준은 `Created`(저장일)** 다.
- 실제 사고 사례: `캠프다온 / 짹짹이야`는 `Created 2026-06-30`, `업로드 날짜 2026-07-01`. **6월 정산에 이미 지급 완료**됐는데, `업로드 날짜`로 필터하면 7월 정산에 다시 잡혀 **이중 지급**된다.
- 대사 스크립트는 항상 `Created` 기준으로 필터할 것.

## 1. 데이터 흐름 — 레인 2개가 `캠핑장 레코드 id`로 만난다

```
[돈 들어오는 쪽]  캠핑장 프리미엄 협찬 신청
                 → Airtable `캠지기 모집 폼` 의 `입금내역 확인` 체크
                 → 시트 탭 『캠핑장 정산_Raw』 (모집인원 / 실입금 금액 / 캠핑장 레코드 id)

[돈 나가는 쪽]    크리에이터 입실일 +14일 내 콘텐츠 전달
                 → 콘텐츠 등록 시 `협찬의 종류` = **프리미엄 협찬**
                 → 시트 탭 『콘텐츠 제작 완료 (크리에이터)』 (협찬비 + 캠핏 수수료)

                        ↕ 조인 키 = 캠핑장 레코드 id
```

### 시트 탭 구성 (실측)
| 탭 | 내용 |
|---|---|
| **캠핑장 정산_Raw** | 상단 `협찬 매출 요약`(확정매출/공급가액/부가세/모집비용/마진/검증) + 캠페인별 행 |
| **콘텐츠 제작 완료 (크리에이터)** | 콘텐츠 저장일 순 원장. `정산 요약`(인별 집계) + `정산 상세`(건별) 블록 포함 |
| 전자세금계산서 업로드 양식 | 국세청 일괄발급용 (캠핑장 대상, 귀속연월 입력칸 있음) |
| 캠지기 관리시트 | 캠핑장 사업자/계좌 마스터 |

## 2. 지급액 수식 (실측 검증 완료)

| 구분 | 수식 | 검증 예 |
|---|---|---|
| **개인** | `협찬비 × 0.967` (원천징수 3.3% 공제) | 80,000 → 77,360 / 130,000 → 125,710 / 240,000 → 232,080 |
| **사업자** | `협찬비 × 1.1` (부가세 10% 가산) | 240,000 → 264,000 / 130,000 → 143,000 |

- `협찬비(크리에이터)`는 **크리에이터 등급별 금액**: 등급 3 = `⭐️ 협찬 제안 금액`, 2 = `✔️`, 1 = `🔥`.
- `협찬비(캠지기)` = `협찬비(크리에이터)` + `캠핏 수수료`. 캠지기가 낸 돈이지 크리에이터 지급액이 아니다.
- ⚠️ **캠핏 수수료 0원인 캠페인이 실재한다** (실측 7건). 프렌들리 플래그와 무관하며, 그 캠페인은 `실입금 = 협찬비 합계`로 정합한다. 0원이라고 무조건 오류로 판단하지 말 것. 단, 수수료 0 = 캠핏 마진 0이므로 매출 요약에서 마이너스 마진으로 보일 수 있다.

## 3. 매월 체크리스트

### ① 에어테이블 ↔ 시트 대사 (누락/초과 찾기)
먼저 구글시트에서 **파일 → 다운로드 → Microsoft Excel(.xlsx)** 로 통파일을 받는다. 그다음:
```bash
node tools/settlement/verify-month.cjs 2026-07 ~/Downloads/"프리미엄 협찬 정산(2026년).xlsx"
```
- 에어테이블 `Created` 기준 전월 프리미엄 건을 뽑아 시트 『콘텐츠 제작 완료_ (크리에이터)』 탭 행과 1:1 대조하고, **저장일·등급·협찬비·캠핏수수료 값까지** 비교한다.
- **에어테이블에 있는데 시트에 없음** → 시트 동기화 지연. 시트에 수동 추가.
- **시트에 있는데 에어테이블에 없음** → 크리에이터가 레코드를 지웠거나 수기 오입력. 원인 확인 전 지급 금지.

> 📌 2026-07 실측: 에어테이블 23건 ↔ 시트 23행, **값까지 전부 일치**했다. 동기화 자체는 잘 돌고 있다. 문제는 아래 ③의 파생 열이었다.

### ② 중복 저장 걸러내기 (이중 정산 방지)
크리에이터가 실수로 두 번 저장하는 일이 있다. 3가지 축으로 본다.
1. **동일 크리에이터 + 동일 캠핑장 레코드 id** — 같은 협찬 건 중복 저장
2. **동일 콘텐츠 링크** — 링크만 재제출
3. **전월 정산분과 겹치는지** — `Created`가 경계일(말일/1일)인 건은 지난달 시트 원장을 직접 조회해 대조

### ③ 시트 파생 열·수식 검증 ← **여기가 매달 실제로 터지는 지점**
행이 들어와도 **수식/파생 열은 자동으로 안 채워진다.** 2026-07 실측에서 23행 전부 아래 열이 공란이었다.
- [ ] `지급액` — 23/23 공란이었음. **채우지 않으면 이체 금액이 없다.**
- [ ] **`협찬비(캠지기)`** — 23/23 공란. 🚨 **이게 비면 『프리미엄 협찬 정산』 탭 전체가 망가진다** (아래 참조)
- [ ] `정산 기준일` — 23/23 공란
- [ ] `사업자번호(캠핑장)` — 23/23 공란
- [ ] `정산 정보 확인` — 23/23 공란 (6월 행은 전부 `완료`)

> 🚨 **`협찬비(캠지기)` 공란 → 캠핏 마진 대량 음수.**
> 『프리미엄 협찬 정산』 탭의 `캠핏 수수료`(O열, **실제로는 확정 거래액**)는 `SUMIFS(콘텐츠 제작 완료!협찬비(캠지기)) × 1.1`이다.
> 반면 `모집 확정금액`(N열)은 `협찬비(크리에이터)` 합이라 정상 집계된다.
> 그래서 이 열이 비면 **매출만 0이 되고 비용은 그대로** → `캠핏 마진 = 공급가액 − 모집확정금액`이 음수로 뒤집힌다.
> 2026-08-03 실측: 마진 음수 15건 전부 이 원인. **`협찬비(캠지기) = 협찬비(크리에이터) + 캠핏 수수료`로 채우면 15건 → 0건.**
- [ ] 『크리에이터 정산』 탭 `정산기준월` 셀을 **이번 달로 변경** (2026-08-03 시점 `2026.6`으로 남아 있었음)
- [ ] 같은 탭 `#N/A` 잔존 여부 (2026-08-03 시점 12개 셀)
- [ ] 인별 합계 = 건별 합계와 일치하는지
- [ ] 『캠핑장 정산_raw』 `협찬 매출 요약`의 `검증` 셀이 `TRUE`인지

### ④ 크리에이터 확인 카톡 발송
두 갈래로 나뉜다.

**(a) 기존 정산자** (이전에 한 번이라도 정산받은 사람)
> 캠핑장별 **협찬비**와 입금 예정일을 적고, 기존 등록 정산정보로 처리됨을 알린 뒤 `변경없음` 회신 요청.

**(b) 첫 정산자**
> **통장사본**을 요구하고 → **계좌번호 / 은행 / 예금주** 3가지를 대조 확인하는 절차를 거친다.

**🚫 실지급액(원천징수 차감 후 금액)은 카톡에 쓰지 않는다.**
`원천징수세(3.3%) 공제 후 등록하신 계좌로 {N+1}/10 입금 예정입니다.` 라고만 안내한다. 크리에이터에게 알리는 건 **협찬비**이고, 차감 후 금액을 숫자로 박으면 소수점·반올림 문의가 붙는다. (사업자 건은 예외 — 계산서 발행을 위해 공급가액·부가세·합계를 명시해야 한다.)

**카톡 템플릿 — 개인**
```
{채널명}님, 안녕하세요! 캠핏입니다 🏕️
{YYYY}년 {N}월 협찬 콘텐츠 정산 안내드려요.
▪ {캠핑장} 협찬 건: {협찬비}원
원천징수세(3.3%) 공제 후 등록하신 계좌로 {N+1}/10 입금 예정입니다.
▪ 입금 계좌: {은행} {계좌번호} (예금주 {예금주})
📌 기존 등록하신 정산 정보 변경 없으신지 '변경없음' 회신 부탁드립니다.
```
캠핑장이 여러 곳이면 `▪ {캠핑장} 협찬 건: {금액}원`을 줄바꿈으로 나열하고 그 아래 `합계 {협찬비 합계}원,` 을 붙인다.

**카톡 템플릿 — 사업자**
```
{채널명}님, 안녕하세요! 캠핏입니다 🏕️
{YYYY}년 {N}월 협찬 콘텐츠 정산 안내드려요. 사업자 정산 건이라 확인 부탁드려요.
1️⃣ 세금계산서 발행
▪ 명목: 크리에이터 협찬 수수료
▪ 공급가액: {협찬비}원 (부가세 10% 별도)
▪ 합계 {협찬비×1.1}원으로 발행 부탁드립니다.
▪ 발행 이메일: finance@nextedition.co.kr
▪ 발행일자: {N}/{말일}
▪ 정산 대상: {캠핑장}
▪ 캠핏 사업자등록증: 카카오톡에 유첨드립니다.
■ 캠핏 발행 정보
▪ 상호: 주식회사 넥스트에디션
▪ 사업자등록번호: 669-88-01204
▪ 대표자: 김동수, 윤우진 (공동대표)
▪ 업태: 정보기술서비스업 / 종목: 콘텐츠, 응용소프트웨어 및 플랫폼 개발공급
▪ 소재지: 서울특별시 강남구 봉은사로 524, 3층 301호 스파크플러스
```

> ⚠️ **캠핏 소재지는 `강남구 봉은사로 524, 3층 301호 스파크플러스`가 맞다.**

- 첫 정산자 판별: 콘텐츠 업로드 테이블에서 그 사람의 **최초 프리미엄 저장건이 이번 달인지**로 판단.
- ⚠️ **성함 ≠ 예금주인 건은 반드시 개별 확인.** 원천징수는 `성함+주민등록번호`로 신고되고 이체는 `예금주`로 나가므로 둘이 다르면 한쪽이 틀린 것이다.

## 3.5 캠핏 지원 건은 정산 대상이 아니다

`캠핏 지원`은 **캠핑장에서 돈을 받지 않고 캠핏이 자기 돈으로 크리에이터 모집을 제공하는 건**이다. 예수금이 아니므로 **매출·부가세·캠핏 마진 개념이 없다.**

| 열 | 지원 건에서의 의미 |
|---|---|
| `가입 금액(선수금)` | ❌ 무의미 (실제로 받은 돈 아님, 명목 금액) |
| `잔여 선수금` | ❌ 무의미 |
| `캠핏 수수료`(=거래액)·`공급가액`·`부가세` | ❌ 항상 0 |
| `캠핏 마진` | ❌ 무의미 (−모집확정금액으로 뜸) |
| **`모집 확정금액`** | ✅ **유일하게 의미 있는 값 = 캠핏이 실제 부담한 비용** |

- 판별: 『캠핑장 정산_raw』 `캠핏 지원`(W열) = TRUE → 『프리미엄 협찬 정산』 X열에 `지원` 표시.
- **요약부(D5:D9, H5:S8)는 이미 `X<>지원` 조건으로 지원 건을 제외**하고 집계한다. 매출·마진 지표는 이미 안전하다.
- 남은 문제는 **목록에 섞여 보이는 것**뿐 → 별도 시트로 분리 + 본 시트에서 필터로 숨긴다.
- ⚠️ **행을 삭제하지 마라.** 에어테이블 동기화로 다시 들어오고 SUMIFS 범위가 깨진다. 반드시 *필터*로 숨긴다.

**별도 시트 만드는 법** (새 시트 이름 `캠핏 지원`, A1에 입력 — 자동 갱신됨)
```
={'프리미엄 협찬 정산'!C12:X12; FILTER('프리미엄 협찬 정산'!C13:X, '프리미엄 협찬 정산'!X13:X="지원")}
```
캠핏 총 부담액:
```
=SUMIF('프리미엄 협찬 정산'!X12:X,"지원",'프리미엄 협찬 정산'!N12:N)
```

## 4. 오답노트

**🚨 구글시트를 MCP 텍스트 변환으로 읽고 대사하지 마라 — 없는 "누락"을 만들어낸다**
2026-08-03 실제 사고: 드라이브 MCP `read_file_content`로 시트를 읽어 "7/29~7/31 4건이 시트에 누락됐다"고 보고했으나 **전부 오류**였다. 원인 두 가지.
1. 변환본이 **뒷부분에서 잘린다.** 『콘텐츠 제작 완료』 탭이 7/28에서 끊긴 채로 넘어왔다.
2. **캐시된다.** 다시 호출해도 바이트 단위로 동일한 결과가 와서, 재확인해도 같은 오답이 반복됐다.
→ **반드시 `.xlsx`를 내려받아 `openpyxl`로 읽을 것.** 실제 파일로 다시 대사하니 23건 전부 일치했다.

**🚨 구글시트를 브라우저 자동화로 조작하지 마라**
같은 사고 때 확인하겠다고 `claude-in-chrome`으로 시트를 열었다가 **이름 상자를 클릭한 줄 알고 셀 A1에 `A75`를 입력해 헤더(`콘텐츠 저장일`)를 덮어썼다.** 게다가 그 크롬은 **팀장님 계정 세션**이었다. 검증은 읽기 전용(다운로드)으로만 하고, 시트 수정은 사람이 직접 한다.

**⚠️ 행이 들어온 것과 정산 준비가 된 것은 다르다**
동기화는 잘 되는데 `지급액`·`정산 기준일`·`사업자번호(캠핑장)`·`정산 정보 확인` 같은 파생 열이 비어 온다. "행 개수 일치"만 보고 넘어가면 금액 없이 이체 요청이 나간다. §3-③를 꼭 돌 것.

**⚠️ `업로드 날짜`로 정산 대상 필터 금지**
→ §0 참조. 이중 지급으로 직결된다.

**⚠️ 계좌번호 필드 오염**
실측: `"3333158546978 카카오뱅크"`처럼 계좌번호에 은행명이 붙어 들어온 건이 있다. 이체 파일 생성 시 오류가 나므로 숫자만 남기고, 원본(에어테이블)도 같이 정정한다.

**⚠️ 같은 사람이 월마다 다른 성함으로 잡히는 경우**
실측: 주민등록번호는 동일한데 6월 시트엔 `강바다`, 7월 시트엔 `곽동화`로 들어간 건이 있었다. 신청 레코드의 `이름`/`예금주` 필드를 각각 다르게 적은 것이 원인. 한 번 확인해서 **에어테이블 원본을 정정**해야 매달 반복되지 않는다.

**⚠️ 같은 캠핑장이 캠페인 레코드 2개로 존재할 수 있다**
예: `산머루농원캠핑장`(recVCmFcf0tmWCKuU, 수수료 20,000)과 `산머루농원`(recqFyYXwMoaYjWlR, 수수료 0)은 별개 모집 회차다. 캠핑장 **이름이 아니라 레코드 id로** 조인할 것.

**⚠️ 크리에이터 채널명 표기가 테이블마다 다르다**
신청 테이블은 `루루캠핑`, 크리에이터 명단은 `lulu_camping(루루 캠핑)`처럼 어긋난다. 채널명 문자열 매칭으로 "제출 안 함"을 판단하면 오탐이 난다. **`크리에이터 명단` 링크 기준**으로 매칭할 것.
