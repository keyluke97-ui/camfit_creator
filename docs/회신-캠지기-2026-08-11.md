## 1. 🔴 §6 전제가 사실과 다릅니다 — 포털은 이미 주민등록번호를 수집합니다

요청서 §6은 이렇게 썼습니다.

> "포털이 정산 정보를 직접 쓰지 않는 현재 구조를 유지할 것"
> "포털이 직접 수집하면 주민번호 처리가 포털 코드로 들어오고…"

**이미 들어와 있습니다.** 프로덕션 `main`에 배포된 상태입니다.

| 위치 | 내용 |
|---|---|
| `app/premium-register/page.tsx` | 프리미엄 협찬 등록 페이지 (JWT 보호) |
| `components/PremiumRegisterForm.tsx:28` | 수집 고지 — *"성명, 생년월일, 연락처, 주민등록번호(또는 사업자등록번호), 계좌 정보, SNS 채널 정보"* |
| `components/PremiumRegisterForm.tsx:298` | `주민등록번호` 입력란 (`- 포함 13자리`) |
| `app/api/premium-register/route.ts` | 정산 테이블 `tblDOC7jcmeuQzNJY`에 기록 |

동의 3종(개인정보 수집·이용 / 콘텐츠 사용 권한 / 지급 조건·원천징수 3.3%)도 이 폼 안에 있습니다.

### 그래서

- **포털이 새로 할 일은 없습니다.** 요청하신 *"미등록자에게 정산 등록 경로 링크 노출"*은 [components/SettlementConfirmCard.tsx](../components/SettlementConfirmCard.tsx)가 이미 하고 있습니다. 미등록이면 `/premium-register`로 보냅니다.
- **회신 요청하신 "정산 등록 폼 URL" = `/premium-register`** 입니다. 외부 폼이 아니라 포털 자체 경로입니다.
- 다만 **개인정보 관리 책임 소재를 다시 잡아주셔야 합니다.** "포털은 고유식별정보를 다루지 않는다"는 전제로 다른 판단을 하고 계시면 어긋납니다.
- 수집 지점은 `/premium-register` **한 곳으로 유지**합니다. 이번 작업에서 늘리지 않습니다.

## 2. `자동수락 활성` 토글을 포털에서 제거합니다

`자동수락 활성`(`fld15wHeuJuwUOf8R`)은 v1 §2.2에서 "인스턴트북 옵트인"으로 정의됐고, 포털에 별도 토글 + 동의 모달로 구현돼 있었습니다.

**이번에 걷어냅니다.** 이유는 그쪽 설계와 모순이 아니라, **오히려 그쪽 설계 때문**입니다.

`지명 제안`(`tbl8uODx66771zsKh`) 테이블 description:

> "A′ 선입금 + **무응답 시 자동확정**. 캠지기 제안 → 선입금 → 입금확인 → 크리에이터 확인창(24~48h) → 확정"

즉 **무응답이면 자동 확정되는 게 이미 전원 기본값**입니다. 여기에 "자동수락 켜기" 토글을 따로 두면 크리에이터는 *"안 켜면 자동확정이 안 되는구나"* 로 읽습니다. 사실과 반대입니다.

### 대신 이렇게 합니다

공개 신청 화면에서 제안 흐름을 6줄로 고지하고, **`'이해'` 타이핑을 받은 뒤에만** 공개할 수 있게 합니다.

> 1. 캠지기가 먼저 입금한 뒤 제안합니다
> 2. 캠핏이 입금을 확인하고 제안서를 이메일로 보내드려요
> 3. 24~48시간 안에 확인해주세요
> 4. **응답이 없으면 수락한 것으로 자동 확정됩니다**
> 5. 거절하실 땐 사유를 적어주셔야 하고, 거절이 반복되면 서비스 이용이 제한될 수 있어요
> 6. 등록하신 채널 전부에 콘텐츠를 올리는 조건이에요

**확인 요청**: `자동수락 활성` 필드를 캠지기 화면이 읽고 있다면 알려주세요. 포털이 더는 쓰지 않으므로 값이 갱신되지 않습니다.

## 3. 🔴 전수 심사를 도입합니다 — 그쪽 리스트 필터 변경이 필요합니다

자기신고 지표는 **크리에이터가 직접 적는 숫자**입니다. 부풀리면 캠지기가 그걸 보고 **선입금**을 합니다. 사후 회수가 어렵습니다.

그래서 **캠핏 확인을 거친 프로필만 노출**하기로 했습니다.

### 상태 흐름

```
미신청 ──[공개 신청]──> 심사대기 ──[운영자 승인]──> 승인 ──> 캠지기에게 노출
                          └──[반려]──> 반려(사유 표시) ──> 재신청 가능

승인 ──[지표·표시물 수정]──> 승인 유지 + `지표 재검토 필요`=true (노출은 계속)
승인 ──[그 외 수정]──> 승인 유지, 즉시 반영
```

**최초 1회만 노출을 막습니다.** 승인 이후의 수정은 노출을 끊지 않고 재검토 큐로만 보냅니다. 그쪽이 확정한 *"프로필은 공개 후에도 상시 수정 가능"*과 충돌하지 않게 하기 위함입니다.

### 🔴 요청 — 리스트 필터 한 줄

| | 필터 |
|---|---|
| 현재 | `프로필 공개 = true` AND `휴먼 상태 ≠ true` |
| 변경 후 | `프로필 공개 = true` AND `휴먼 상태 ≠ true` AND **`프로필 심사 상태 = 승인`** |

**이 한 줄이 빠지면 심사 전 프로필이 그대로 노출되어 전수 심사가 무효가 됩니다.** 상세 화면도 동일 필터가 필요합니다.

## 4. 🔴 §3.2 문구가 사실이 아니게 됩니다

요청서 §3.2에서 넣어달라고 하신 문구입니다.

> "지금 공개하시면 조건에 맞는 제안이 **바로** 들어와요."

3번의 심사가 생기면서 **바로 들어오지 않습니다.** 공개 신청 → 캠핏 확인 → 그다음입니다.

포털은 아래로 바꿔 씁니다. 캠지기 화면에도 같은 전제로 반영해주세요.

> 캠핏 확인 후 캠지기에게 보입니다 (보통 1영업일)

뒤 문장(*"제안이 들어온 뒤에 금액·조건을 바꾸셔도 그 제안에는 적용되지 않습니다"*)은 **그대로 씁니다.** `조건 스냅샷` 근거도 확인했습니다.

## 5. 금액은 크리에이터가 정한 대로만 제안되게 해주세요

§5.1 문구(*"등록하신 채널 전부에 콘텐츠를 올리는 조건의 금액"*)는 그대로 넣습니다.

추가로 **라벨 자체를 바꿉니다.**

| | 문구 |
|---|---|
| 기존 | 최소 협찬 단가 (이 금액 **이상** 제안만 받아요) |
| 변경 | 협찬 금액 — 캠지기가 **이 금액으로** 제안합니다 |

"이상"은 협상 여지가 있다는 오해를 줍니다.

**캠지기가 제안 폼에서 금액을 바꿀 수 있습니까?** 바꿀 수 있다면 포털 문구가 거짓말이 됩니다. **크리에이터의 `협찬 희망 금액`이 그대로 `제안 금액(크리에이터)`에 들어가도록 고정**해주세요.

## 7. `거절 사유`를 자유 서술로 받을 수 있게 해주세요

`지명 제안`의 `거절 사유`(`fldWEHxZtWLN1giFp`)는 현재 singleSelect 3택입니다 — `일정` / `금액` / `기타`.

크리에이터가 거절할 때 **사유를 적게** 하고, 반복되면 이용을 제한하기로 했습니다(`예외 거부 사용 횟수` `fldu85N9UgwLZjms3` 활용). 그런데 3택으로는 "적게" 할 수가 없고, `기타`가 대부분이 되면 제한 판단 근거도 남지 않습니다.

**기존 3택은 그대로 두고, `거절 상세 사유`(multilineText)를 하나 추가**해주세요. 1b(제안 확인 화면)에서 씁니다.

## 8. `블로그 지수(자기신고)` 상수가 요청서에 빠졌습니다

요청서 §3.4에 `REPRESENTATIVE_CHANNELS`와 `CONTENT_FORMATS`는 있는데 블로그 지수가 없습니다.

그리고 §2 표의 `최적1~4`는 **축약 표기**입니다. 실제 옵션은 개별 7종입니다.

```ts
export const BLOG_INDEX_LEVELS: string[] = [
  '최적1', '최적2', '최적3', '최적4', '준최5', '준최6', '저품질',
];
```

§4-6("신규 select 값은 화이트리스트 검증")을 지키려면 이 상수가 필요해서 포털에 추가했습니다. `camfit-premium/netlify/functions/shared-constants.js`에도 동기화해주세요.

**확인 완료한 것** — `CONTENT_FORMATS` 6종과 `REPRESENTATIVE_CHANNELS` 3종은 Airtable 실제 옵션과 **완전 일치**합니다.

### 폼 구조는 탭으로 갑니다

§3.5 제안(섹션 1에 채널 블록 + 섹션 3 신설)에서 한 발 더 나갑니다.

```
운영 중인 채널 체크 → 체크한 것만 탭 생성
┌─ 인스타 ─┬─ 유튜브 ─┐
│ 채널 주소 / 규모 / 두 번째 지표 / 채널 강점
└──────────────────
대표 채널 지정
```

- 유튜브를 안 하면 유튜브 입력란이 **아예 안 뜹니다**
- `제작 콘텐츠 형식`도 보유 채널의 것만 노출합니다 (§4-3 위반이 애초에 불가능)
- **필수는 최소로 둡니다** — 지표는 선택. 대신 완성도 바로 *"채우면 제안을 더 받아요"* 유도. 그쪽 §3.3의 "등록 마찰" 경고에 동의합니다
