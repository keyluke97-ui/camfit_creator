## 1. 🔴 가장 큰 것 — 크리에이터가 제안을 **거절할 방법이 없습니다**

### 무슨 일이 벌어지나

포털 공개 화면이 크리에이터에게 이렇게 약속합니다.

> 1. 캠지기가 **먼저 입금한 뒤** 제안합니다
> 2. 캠핏이 입금을 확인하고 제안서를 이메일로 보내드려요
> 3. **24~48시간 안에 확인해주세요**
> 4. **응답이 없으면 수락한 것으로 자동 확정됩니다**
> 5. **거절하실 땐 사유를 적어주셔야** 하고, 거절이 반복되면 서비스 이용이 제한될 수 있어요

그런데 **확인·수락·거절할 화면이 어느 쪽에도 없습니다.**

실측:
- 포털 `app/dashboard/` = `page.tsx`, `portfolio` 둘뿐. 제안 관련 라우트 없음
- 포털 `app/api/` 에 제안 관련 엔드포인트 없음
- 캠지기 레포 전수 검색 → `예외거부`·`크리에이터확인중`이 **문서(.md)에만** 있고 코드에 없음

### 그래서 실제로 이렇게 됩니다

```
캠지기가 선입금  →  제안서 이메일 발송  →  크리에이터: 확인·수락·거절할 곳이 없음
```

**캠지기 돈이 이미 들어온 상태에서 제안이 갈 곳을 잃습니다.** 약속한 3·4·5번이 그대로 깨집니다.

> ⚠️ 처음엔 "무응답이니 전원 자동 확정되겠구나" 생각했는데, **자동화까지 확인해보니 자동 확정도 없습니다**(§5-①). 확정도 안 되고 거절도 안 되고 그냥 멈춥니다.

### 이미 스펙은 있습니다

`camjigi_claude/docs/[spec] 크리에이터포털_지명형_제안수신함_빌드스펙_20260715.md`
— **대상 repo가 우리 포털**로 명시된 자기완결 지시서입니다. 2026-07-15에 나왔고 **구현이 안 됐습니다.**

### 결정이 필요합니다

## 2. 🔴 오픈은 한 번이 아니라 **두 단계**입니다

```
1단계 · 크리에이터에게 오픈
   배포 → 온보딩 안내 발송 → 프로필 채워짐 → 심사 → 승인
                                                    ↓
2단계 · 캠지기에게 오픈
   승인된 크리에이터가 쌓인 뒤에야 리스트가 쓸모 있음
```

**둘을 같이 열면 캠지기가 빈 리스트를 봅니다.** 첫인상이 "아무도 없네"면 다시 안 들어옵니다.

**정하셔야 할 숫자: 2단계로 넘어가는 기준이 승인 몇 명인가?**

## 4. 🟡 놓치기 쉬운 것 — 제가 확인하면서 발견한 것들

### 4-1. 심사 결과를 크리에이터가 모릅니다

승인·반려 시 **아무 알림도 안 나갑니다.** 크리에이터가 포털에 다시 들어와야 압니다.

반려일 때 특히 문제입니다 — 고쳐야 할 게 있는데 고치라는 말을 들을 방법이 없습니다.
(반려 사유를 화면에 보여주는 코드는 있습니다. 다시 들어와야 볼 뿐입니다.)

**정하실 것:** 카톡/메일 알림을 붙일지, 아니면 심사자가 수동으로 연락할지.

### 4-2. 포트폴리오 페이지에 개인정보 수집 고지가 없습니다

이 페이지는 이메일·채널 URL·지표·콘셉트를 받아 **캠지기에게 공개**합니다.
공개 시 *"공개되며, 사실과 다르면 협찬이 무효가 될 수 있어요"* 라는 안내는 있지만,
`/premium-register`에 있는 것 같은 **개인정보 수집·이용 동의 고지는 없습니다.**

법무 판단이 필요한 영역이라 단정하지 않겠습니다. **오픈 전 확인 대상으로 올립니다.**

### 4-3. 승인 후 이미지만 바꾸면 재검토가 안 걸립니다

지표·링크·채널을 고치면 `지표 재검토 필요`가 서는데, **프로필 이미지만 교체하면 아무 플래그도 안 섭니다.**
이미지가 PATCH payload에 없어 서버가 변경을 알 방법이 없기 때문입니다.

막으려면 업로드 라우트(`/api/creator/profile/image`)에서 승인 상태일 때 플래그를 세워야 합니다.
**심사를 통과한 이미지와 다른 이미지가 노출될 수 있다는 뜻입니다.**

### 4-4. 포인터 클릭 검증이 안 됐습니다

Task 15 12개 항목은 전부 통과했지만, **JS로 React 핸들러를 직접 발화**시킨 결과입니다.
브라우저 자동화의 포인터 클릭이 이 환경에서 죽어 있었습니다(원인: `document.hidden=true`로 rAF 정지 — 캠지기측 진단).

상태 변화·저장·서버 검증은 실제로 태웠지만, **"요소가 가려져 실제 손가락으로는 안 눌리는"** 종류는 못 잡습니다.
375px에서 뷰포트 밖 요소 0개·가로 스크롤 없음은 확인해 위험을 줄였을 뿐입니다.

**사장님이 직접 눌러보시는 것(Task 15 Step 4)이 이 구멍을 메웁니다.**

### 그런데 없는 자동화가 있습니다 — 이게 §1과 합쳐지면 심각합니다

**① 크리에이터 응답 기한 만료 → 자동 확정** — **없습니다**

화면은 *"응답이 없으면 수락한 것으로 자동 확정됩니다"* 라고 약속합니다.
그런데 위 3개 중 **어느 것도 `크리에이터확인중`을 다음 상태로 옮기지 않습니다.** 그 일을 하는 자동화가 아예 없습니다.

§1(제안 수신함 없음)과 겹치면 이렇게 됩니다.

```
캠지기 선입금  →  제안서 메일  →  상태 = 크리에이터확인중
                                        ↓
                        수락할 곳 없음 · 거절할 곳 없음 · 자동 확정도 없음
                                        ↓
                              영원히 크리에이터확인중
```

**캠지기 돈은 이미 들어와 있는데 제안이 어디로도 못 갑니다.** 앞서 "무응답이면 자동 수락된다"고 적었는데, 자동화를 확인해보니 **자동 수락조차 안 됩니다.** 그냥 멈춥니다.

**② 프로필 심사 대기 알림** — 없습니다

크리에이터가 공개 신청하면 `심사대기`가 되는데 **아무도 모릅니다.** 슬랙 알림이 없으면 §3-1의 "1영업일"을 지킬 방법이 없습니다.
(프리미엄 쪽엔 같은 패턴이 이미 있습니다 — `프리미엄 협찬 일간 알림봇`, 매일 14시 cron)

**③ 심사 결과 → 크리에이터 알림** — 없습니다 (§4-1과 같은 건)
