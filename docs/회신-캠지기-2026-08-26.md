### Q1(3) 화이트리스트 — 초안에서 한 개 바뀌었습니다

```
초안   상태 · 응답 일시 · 거절 상세 사유 · 예외거부 일시
확정   상태 · 응답 일시 · 거절 사유 · 거절 상세 사유
```

`예외거부 일시`를 뺐습니다. Q1(2)에서 **확인 창 거절은 `예외거부`가 아니라고** 합의했으니
포털이 그 필드를 쓸 일이 애초에 없습니다. 대신 거절 시 실제로 필요한 `거절 사유`(일정/금액/기타)를 넣었습니다.

`멱등키`·`버전`은 금지 유지입니다. 낙관적 잠금 대신 **`응답 일시`가 비어 있을 때만 응답 처리**합니다 —
운영자가 Airtable UI로 직접 고치는 게 정상 경로인데 UI는 버전을 올리지 않아, 버전 잠금은
안전해지지 않고 안전하다는 착각만 만듭니다.

이 4개는 `tools/jimyeong/verify-contract.ts`가 강제합니다. 늘어나면 CI가 아니라 **검증이 FAIL**합니다.

## 2. 🔴 확인 창이 시간에서 영업일로 바뀌었습니다

권고해주신 48시간을 사장님이 **2영업일로 바꿨습니다.** 이유는 그쪽 권고의 근거와 같은 방향입니다:

> 절대시간은 **받은 요일에 따라 실제 여유가 달라집니다.**
> 금요일 저녁에 받으면 일요일 저녁이 마감이라 손쓸 시간이 없고, 화요일 아침에 받으면 이틀이 온전합니다.

**포털 구현 (완료)**

```
마감 = 발송 다음 날부터 세어 2영업일째 되는 날의 23:59:59.999 (KST)

  화 10:00 발송 → 수(1)·목(2)  → 목 자정 직전
  금 18:00 발송 → 월(1)·화(2)  → 화 자정 직전   (48h였다면 일요일 저녁에 잠겼습니다)
  추석 직전 수  → 연휴 전부 건너뛰고 화(1)·수(2)
```

- 상수: `OFFER_RESPONSE_WINDOW_BUSINESS_DAYS = 2` (`lib/constants.ts`)
- 공휴일: `KR_HOLIDAYS` 수동 테이블 + `KR_HOLIDAYS_COVERED_THROUGH = '2026-12-31'`.
  **커버리지를 넘어가면 주말만 제외**로 폴백합니다 — 모르는 공휴일을 추측하지 않습니다
- 계산은 **KST 달력 고정**입니다. 서버가 UTC라 로컬 타임존에 의존하면 자정 근처에서 하루가 밀립니다
- `verify-rules` 107 → **114 passed** (주말·연휴·대체공휴일·폴백·KST 경계 케이스 추가)

**그쪽에 필요한 것 3가지**

1. **`CREATOR_REVIEW_WINDOW_HOURS`(시간 단위)는 더 이상 대응되지 않습니다.** 같은 값을 유지하자고
   합의했던 상수인데, 이제 단위 자체가 다릅니다. 영업일 계산으로 바꾸시거나, 마감을 포털이 계산한
   값 하나만 쓰도록 정리해야 **양쪽이 같은 마감을 말합니다**
2. **공휴일 테이블을 공유해야 합니다.** 양쪽이 각자 관리하면 연휴마다 하루씩 어긋납니다.
   저희 테이블을 단일 소스로 쓰시겠습니까, 아니면 그쪽 것을 쓸까요
3. **약관·제안 메일 문구.** 포털 고지는 *"제안서를 받으시면 2영업일 안에 수락 또는 거절로 회신해주세요
   (주말·공휴일은 세지 않아요)"* 로 고쳤습니다. 약관 v1.2와 메일이 아직 "24~48시간"이면
   **크리에이터가 서로 다른 마감을 두 곳에서 봅니다**

## 3. 🔴 제안 메일에 쿠폰 코드를 넣지 마세요

*"거절해도 쿠폰이 이미 손에 있고 회수 절차가 없다"* 는 지적, 맞았습니다.
사장님 답은 **발행 시점과 노출 시점을 분리**해서 그 리스크를 없앱니다.

```
캠지기 신청 → 입금확인 → 쿠폰 발행(수기) → 제안 발송   ← 여기까지 코드는 안 보입니다
                                             ↓ 수락
                                       이미 발행된 코드를 그때 보여줍니다
```

- 발행을 확정 뒤로 미루면 **운영자가 한 번 더 일합니다**(수기라). 그래서 발행은 앞에 둡니다
- 대신 **코드를 안 보여주면 거절자는 코드를 가진 적이 없습니다.** 회수 절차를 만들어 지키는 대신
  **지킬 게 없게** 만든 겁니다
- 거절·무응답 건의 코드는 아무도 본 적이 없으므로 **그대로 다음 제안에 재배포**합니다

**그래서 부탁드립니다** — 「제안서 발송」 자동화의 **메일 본문에 `크리에이터 쿠폰 코드`를 넣지 마세요.**
메일엔 포털 링크(`/dashboard/offers`)만 보내주시면 됩니다. 메일에 코드가 들어가는 순간
위 구조가 통째로 무너지고, 저희가 화면에서 가리는 건 의미가 없어집니다.

포털도 같은 원칙을 지킵니다: `크리에이터확인중` 상태에서는 **API 응답에도 코드를 담지 않습니다.**
화면에서만 가리면 개발자도구로 보입니다(파트너 쿠폰 풀 노출을 막았던 것과 같은 이유).
