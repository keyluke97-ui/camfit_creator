# SOP — 프리미엄 협찬 무효 처리

> 크리에이터가 실제 방문·숙박 없이 콘텐츠를 게시했거나, 협찬 이행이 성립하지 않은 건의 처리 기준.
> 최초 작성: 2026-07-08 (레인보우 관광농원 / c.c.c_rara 건 계기)

---

## 1. 대전제

**협찬 무효·원고료 미지급은 "제재"가 아니라 미이행에 따른 당연한 결과다.**
제재(참여 제한)는 별도 판단이며, 아래 §3 계단을 따른다. 두 개를 섞지 말 것.

프리미엄 협찬의 구조:

```
[캠지기 숙박권 제공] + [캠핏 원고료]  ↔  [실제 방문·숙박 경험 기반 콘텐츠]
```

숙박이 실제로 이뤄지지 않았다면 반대급부가 성립하지 않는다. 콘텐츠 게시 여부와 무관하다.

---

## 2. 근거가 되는 신청 단계 정책

크리에이터가 신청 시 동의한 항목([ApplicationModal.tsx](../components/ApplicationModal.tsx) Step 1~3):

| 조항 | 내용 |
|---|---|
| Step 2 ④ **콘텐츠 진정성** | 입실일 이후 촬영 소재로 제작. 과거 방문분·타 캠핑장 영상 재사용 시 협찬 무효 · 원고료 미지급 |
| Step 2 ④ **입실 문제 발생 시** | 콘텐츠 제작 **전에** 운영팀 연락. 크리에이터 귀책 아닌 사유는 불이익 없음 |
| Step 2 ③ **이용 혜택 및 비용 부담** | 혜택은 캠지기가 기재한 숙박권과 원고료에 한함 |
| Step 3 **예약 완료 소식 알리기(필수)** | 입실일·입실 사이트 미등록 시 일반 협찬으로 간주, 원고료 지급 어려움 |

> ⚠️ **Step 1의 「노쇼(No-show)」 조항을 함부로 적용하지 말 것.**
> 노쇼는 *크리에이터가 방문하지 않은 경우*다. 현장까지 갔으나 예약 오류·사이트 중복 점유 등으로 입실하지 못한 건은 노쇼가 아니며, 원인이 캠핑장·예약 시스템 측에 있다. 통보문에 '노쇼'라고 쓰면 크리에이터가 정당하게 반박할 수 있고 캠핏 귀책이 부각된다.

## 3. 제재 계단

| 사유 | 1차 | 재발 |
|---|---|---|
| 사전 고지 없는 미방문·재사용 콘텐츠 | 협찬 무효 + 참여 제한 3개월 | 영구 제한 |
| 허위 입실 등록 등 기만 행위 | 즉시 영구 제한 | — |

> **예외 조항**
> 고의가 없고, 콘텐츠 게시 **전에** 운영팀에 상황을 알린 경우
> → 협찬 무효 · 원고료 미지급으로 **종결**하며, 참여 제한은 적용하지 않는다.
>

## 4. 협찬 무효 시 팔로워 쿠폰 처리 (쿠폰 이벤트 캠페인)

**팔로워는 귀책이 없다.** 크리에이터 제재가 팔로워 불이익으로 전가되면 안 된다.

| 대상 | 처리 |
|---|---|
| 팔로워가 **이미 등록·사용**한 쿠폰 | **유효 유지.** 캠지기 정산도 정상 처리 |
| 미등록 잔여 쿠폰 | 사용 중단. 코드 **재발급·재배포 금지** |
| 크리에이터 본인 예약 쿠폰 | 미사용 시 무효화 |
| 캠지기 | 무효 발생 사실 + 잔여 쿠폰 수 통지 |

## 5. 실행 체크리스트

콘텐츠 게시 전:

- [ ] 크리에이터에게 통보문 발송 (§6 톤 참고)
- [ ] 협찬 표기(`@camfit_official` 태그) 및 팔로워 쿠폰 안내 제거 요청

Airtable 정리:

- [ ] `유료 오퍼 신청 건`(`tblIV8Wk4SLx2Hh91`) — 해당 레코드 `입실일`·`입실 사이트` 초기화, `예약 취소/변경` 기록
- [ ] `인플루언서 컨텐츠 업로드`(`tblta2cow9ymKr68J`) — 해당 레코드 무효 표시
- [ ] `캠지기 모집 폼`(`tblt5o7BJFOXjfT3c`) — 해당 등급 `신청 가능 인원` 복구 여부 판단
- [ ] 팔로워 쿠폰 코드 사용 중단 (캠핏 어드민)

캠지기 대응:

- [ ] 무효 발생 통지
- [ ] 자리 미이행분에 대해 [SOP-프리미엄협찬-인원리밸런싱-환불](SOP-프리미엄협찬-인원리밸런싱-환불.md) 적용 여부 판단
- [ ] ⚠️ 정산 절대규칙: 매칭/모집중 상태의 등급 단가는 변경하지 않는다

## 6. 통보문 톤 가이드

- **캠핏 귀책이 섞인 건이면 먼저 사과한다.** 크리에이터가 현장까지 갔다면 그 사실을 첫 문단에 쓴다.
- '노쇼', '허위', '기만' 같은 단어는 §3 2번째 행에 해당할 때만 쓴다.
- 정책 조항을 나열하지 말고 **한 줄로 압축**한다. ("프리미엄 협찬은 실제 입실과 숙박을 전제로 원고료가 지급되는 구조라…")
- 예외 조항을 적용했다면 **그 사실과 이유를 명시**한다. 관대함이 선례가 아니라 규정임을 알려야 한다.
- 마지막에 재발 방지 경로를 안내한다. ("콘텐츠 제작 전에 먼저 운영팀으로 연락 주세요.")

## 7. 알려진 공백 (미해결)

향후 개선 대상. 현재 정책 문구로만 막고 있다.

- **입실 확인 프롬프트 부재** — [CheckinModal.tsx](../components/CheckinModal.tsx)는 자기신고 `입실일`이 지나면 실제 방문 여부와 무관하게 카드를 '완료'로 표시한다(`isPast = isRegistered && checkInDate < today`). 포털이 먼저 "협찬이 끝났다"고 말하는 셈.
- **입실 문제 신고 경로 부재** — 입실 무산 시 포털이 제공하는 선택지는 `예약 변경`(재방문 필요)과 `신청 취소`(참여 제한·금전적 손해 경고)뿐이다. 크리에이터 귀책이 아닌 사유에도 경고 문구가 붙는다.
- **입실 사실 검증 수단 부재** — `입실일`·`입실 사이트`는 자기신고이며 캠핏 예약 시스템과 대조하지 않는다.

> 세 항목은 하나의 기능(입실일 경과 시 `잘 다녀오셨나요? [네] / [문제가 있었어요]` 프롬프트)으로 해소 가능하다. Airtable 필드 1개 + API route 1개 + 카드 UI 1개 규모.
