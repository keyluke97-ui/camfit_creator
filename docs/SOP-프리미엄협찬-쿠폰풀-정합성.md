# SOP — 프리미엄 협찬 팔로워 쿠폰 풀 정합성 (취소·리밸런싱 시)

> 작성 2026-07-13 · 대상 그로쓰팀 · 데이터 Airtable `캠지기 모집 폼`(캠페인) + `유료 오퍼 신청 건`(신청)
> ⚠️ **쿠폰이벤트 캠페인에서 신청 레코드를 "그냥 삭제"하면 쿠폰이 새서 다음 신청자가 막힌다.** 아래 절차대로.

---

## 0. 목적 & 적용 범위
- **목적**: 쿠폰이벤트 캠페인(`쿠폰이벤트희망=true`)에서 **팔로워 쿠폰 풀이 신청 자리와 어긋나 새는 것**을 막는다. 새면 신청자가 `COUPON_POOL_EMPTY`("팔로워 쿠폰이 일시적으로 부족합니다")를 맞고 신청을 못 한다.
- **적용**: 쿠폰이벤트 캠페인의 **신청 취소 처리**, 그리고 그 캠페인의 **인원 리밸런싱**([SOP-프리미엄협찬-인원리밸런싱-환불](SOP-프리미엄협찬-인원리밸런싱-환불.md)과 함께 볼 것).

---

## 1. 핵심 원리 — 카운터 두 개가 같이 움직여야 한다
쿠폰이벤트 캠페인엔 **독립된 카운터 2개**가 있고, 신청할 때는 [applyCampaign](../lib/airtable.ts)이 둘을 같이 깎는다.

| 카운터 | 필드 | 정체 |
|---|---|---|
| **열린 자리** | `총 신청 가능 인원` (등급별 `✔️/⭐️/🔥 신청 가능 인원` 합) | 모집인원 − 신청 레코드 링크 수 (공식) |
| **쿠폰 풀** | `팔로워 쿠폰 코드` (줄바꿈 목록) | 아직 안 나간 쿠폰 코드. 신청 시 맨 위 1줄이 빠져 `배포 완료된 쿠폰`으로 이동 |

### 🚨 지켜야 할 불변식
> **`풀 줄 수` ≥ `총 신청 가능 인원`**

이게 깨지면(자리는 있는데 코드 없음) 다음 신청 시 무조건 `COUPON_POOL_EMPTY`.

### 불변식을 깨는 두 작업
1. **신청 취소(레코드 삭제)** — 자리는 +1 되는데 **쿠폰은 풀로 안 돌아온다** → 항상 깨는 방향. **§3 절차 필수.**
2. **인원 리밸런싱** — 쿠폰은 어드민이 "그 시점 모집인원" 기준으로 한 번만 발행하는데, 리밸런싱은 그 뒤 자리 수를 바꾼다.
   - 자리 **축소**(예: 라이징2→파트너1): 코드가 남는 방향 → 안전(잉여만 생김).
   - 자리 **증설**: ⚠️ 코드 부족 방향 → **§4대로 풀 보충** 안 하면 취소 하나 없어도 터진다.

## 3. 🚨 신청 취소 절차 (쿠폰이벤트 캠페인)

**레코드를 그냥 삭제하지 말 것.** 삭제 전에 쿠폰을 풀로 반납해야 한다.

### 방법 A — 툴 사용 (권장, 실수 불가)
```bash
# 1) 계획 확인 (dry-run, 아무것도 안 씀)
node tools/coupon-pool/cancel-application.cjs <신청레코드ID>
# 2) 실행 (코드 반납 + 검증 후 삭제)
node tools/coupon-pool/cancel-application.cjs <신청레코드ID> --commit
```
툴이 자동으로: 본인 코드 → 캠페인 `팔로워 쿠폰 코드` 풀에 추가 + `배포 완료된 쿠폰`에서 제거 → 검증 → 레코드 삭제(자리 +1 자동 복구).

### 방법 B — 수동 (툴 못 쓸 때)
1. 취소할 **신청 레코드의 `팔로워 쿠폰 코드`**(본인 코드)를 복사.
2. 캠페인 `팔로워 쿠폰 코드`(풀) **맨 아래에 그 코드를 한 줄 추가**.
3. 캠페인 `배포 완료된 쿠폰`에서 **그 코드 줄을 삭제**. ⚠️ **이 스텝을 빠뜨리면** 재분배 시 코드가 배포완료에 2번 찍혀 신규 신청자가 엉뚱하게 `CAMPAIGN_RACE`로 롤백된다.
4. 그다음 신청 레코드 삭제.

> 쿠폰이벤트가 **아닌** 일반 캠페인은 그냥 삭제해도 된다(반납할 코드 없음).

## 4. 리밸런싱으로 자리를 늘렸을 때 — 풀 보충
쿠폰이벤트 캠페인의 한 등급 자리를 **늘렸다면**, 늘린 만큼 풀에 코드가 더 있어야 한다.
1. 리밸런싱 후 `node tools/coupon-pool/audit.cjs` 실행.
2. 해당 캠페인이 `풀 < 열린자리`(⚠️)로 뜨면 → **어드민 쿠폰 자동발행**으로 부족분을 풀에 채운 뒤 오픈.
3. 자리를 **줄인** 경우엔 코드가 남을 뿐이라 조치 불필요(잉여는 미사용으로 만료).

## 5. 주간 감사 (안전망)
```bash
node tools/coupon-pool/audit.cjs
```
- `🔴 노출中` + `풀부족 ⚠️` = **지금 실제로 터지는 캠페인** → 즉시 §3/§4 조치.
- `붕뜬코드 > 0` = 취소했는데 코드 반납이 안 된 흔적. 살아있는 신청 수와 배포완료 수를 대조해 반납.
- `⚪ 미노출`(입금내역 확인=false) = 오픈 전이라 당장 무해(단, 오픈 전 풀 채웠는지 확인).

**주기: 매주 1회 + 리밸런싱/대량 취소 직후.**

## 6. 터졌을 때 응급 처치 (COUPON_POOL_EMPTY 문의 접수 시)
1. 캠페인을 `search_records`로 조회 → `팔로워 쿠폰 코드`(풀)와 `배포 완료된 쿠폰`, `총 신청 가능 인원` 확인.
2. **붕 뜬 코드 = `배포 완료된 쿠폰` 중, 살아있는 신청들이 쥔 코드를 뺀 나머지.**
   - 살아있는 신청들의 코드 = `유료 오퍼 신청 인플루언서`가 가리키는 각 신청 레코드의 `팔로워 쿠폰 코드`.
3. 붕 뜬 코드를 `팔로워 쿠폰 코드`(풀)로 옮기고 `배포 완료된 쿠폰`에선 제거(§3 방법 B 3번과 동일 원리) → 풀 ≥ 열린자리 되면 신청 재개.
4. 붕 뜬 코드가 없는데 풀이 비었다면(유형 B) = 애초에 발행이 안 된 것 → 어드민 자동발행으로 풀 채움.
