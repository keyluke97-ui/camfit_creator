## 3. 🔴 열어두신 질문에 대한 답 — **네, 뜰 수 있습니다**

> 동반 인원 0인 레거시가 심사를 통과해 리스트에 뜰 수 있는지

**게이트는 저장 시점에만 도는 문지기라, 이미 안에 있는 사람은 못 내보냅니다.**

- **신규 공개 신청**: 못 뚫습니다. `400 INCOMPLETE ["동반 인원"]` 실측 확인.
- **이미 `공개=true`인 레거시**: 아무도 저장을 안 하면 게이트가 돌지 않아 **동반 인원 없이 계속 노출**됩니다.

그리고 **2차 증상이 더 고약합니다.** 그 레거시가 나중에 *다른 것만* 고치려고 저장을 누르면 동반 인원 때문에 400이 나는데, 화면엔 `"입력 조건을 확인해주세요."`만 뜹니다. **본인이 건드린 적 없는 항목 때문에 막히고, 이유를 알 수 없습니다.**

선택지 셋 중 **(a)를 권합니다.**

| | 방법 | 평가 |
|---|---|---|
| **(a)** | 오픈 전 백필 | **지금 실데이터가 0명이라 비용도 0.** 오픈 후에는 이 창이 닫힙니다 |
| (b) | 캠지기측 리스트 필터에 `동반 인원 > 0` | 노출은 막지만 크리에이터는 자기가 왜 안 보이는지 모름 |
| (c) | 위반 코드를 항목별 한국어로 매핑 | (a)와 무관하게 해두면 좋음. 신규 3종만이 아니라 기존 8종에도 적용 |

**(a)는 지금이 아니면 못 합니다.** 실제 크리에이터가 한 명이라도 공개하는 순간 백필 대상이 생깁니다.

## 4. 제안 — 스키마는 문서 말고 **검사 스크립트**로

이번에 오간 문서에서 분량 대부분이 *"필드 이름·타입·옵션이 이렇습니다"* 였습니다. 그런데 그건 **이미 Airtable에 있는 사실**이고, 산문으로 옮기는 순간 실물과 어긋나도 아무도 모릅니다.

포털 쪽에 `tools/jimyeong/verify-contract.ts`를 넣었습니다. 양쪽이 같은 걸 돌리면 됩니다.

```
ok    업로드 기한(일) (number)
ok    동반 인원 (number)
ok    반려동물 동반 (checkbox)
ok    드론 촬영 (checkbox)
ok    채널콘셉트(자기신고) (multipleSelects)
ok    채널콘셉트 (multipleSelects)
ok    표준 기한 14일 == overdue.cjs GRACE_DAYS

계약 일치 — 스키마 드리프트 없음
```

타입 불일치·필드 누락·옵션 불일치 세 종류를 잡고 **불일치면 exit 1**로 죽습니다(일부러 어긋나게 만들어 확인했습니다). 한쪽이 필드를 지우거나 옵션을 바꾸면 반대쪽에서 즉시 드러납니다.

**그래서 앞으로 문서에 담을 것은 이것만입니다** — 결정과 그 이유, 열어둔 질문, 서로에게 부탁하는 일. 스키마는 스크립트가 말하게 둡시다.
