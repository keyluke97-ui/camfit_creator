# PRD: 파트너 협찬 기능 완성 (v2)

> 작성일: 2026-04-07
> 상태: Draft
> 기준: 프리미엄 협찬 (ApplicationModal / CheckinModal / CampaignCard) 대비 파트너 협찬 갭 분석

---

## Problem Statement

파트너 협찬 기능이 배포되었으나, 프리미엄 협찬 대비 **쿠폰 발급 UX, 정책 안내, 숙소 정보 표시, 에러 처리** 등 핵심 로직이 다수 누락되어 있다. 크리에이터가 신청 완료 후 즉시 행동(쿠폰 등록, 예약)으로 연결되지 않아 전환율이 떨어지고, 캠지기(캠핑장 운영자)를 위한 파트너 협찬 신청 페이지도 아직 존재하지 않아 운영팀이 수기로 Airtable에 데이터를 입력하고 있다.

---

## Goals

1. 프리미엄 협찬과 동일한 수준의 크리에이터 UX 완성 (쿠폰 즉시 발급, 정책 안내, 에러 처리)
2. 캠지기가 직접 파트너 협찬을 등록할 수 있는 신청 페이지 구축 (운영팀 수기 입력 제거)
3. 신청 완료 → 쿠폰 등록 → 예약까지의 전환율 극대화

---

## Non-Goals

1. **파트너 협찬에 등급(Tier) 시스템 도입** — 파트너는 등급 구분 없이 통합 운영 (CLAUDE.md 규칙)
2. **할인 금액 하드코딩** — 평일/주말 할인은 반드시 Airtable에서 조회 (CLAUDE.md 규칙)
3. **캠지기 대시보드 전체 구축** — v2에서는 신청 폼만, 관리 대시보드는 별도 스펙
4. **결제/정산 시스템 통합** — 기존 수기 정산 프로세스 유지

### B2. 캠지기 인증 방식

**Open Question:** 캠지기 전용 로그인이 필요한가, 아니면 비인증 폼(URL 공유)으로 충분한가?

**옵션 A — 비인증 폼 (권장, v1)**
- 별도 URL (`/partner-apply` 또는 `/partner/register`)
- 사업자번호 + 연락처로 중복 신청 방지
- 장점: 빠른 구현, 캠지기 진입 장벽 낮음
- 단점: 스팸 신청 가능성

**옵션 B — 캠지기 로그인**
- 사업자번호 + 비밀번호 기반 별도 인증
- 장점: 보안, 신청 내역 관리
- 단점: 구현 복잡도 증가, v2 스코프 초과 가능

### B3. 폼 UX 설계

**단계 구성:**
1. **Step 1: 캠핑장 기본정보** — 캠핑장명, 대표자명, 연락처, 이메일, 사업자번호, 소재 권역
2. **Step 2: 협찬 조건 설정** — 패키지, 숙박타입, 할인금액, 공휴일 적용, 모집인원, 팔로워쿠폰수
3. **Step 3: 기간 설정** — 방문 가능 기간, 쿠폰 유효 기간
4. **Step 4: 숙소 소개** — 텍스트에어리어
5. **Step 5: 정책 동의** — 취소/변경 불가 정책 동의
6. **Step 6: 최종 확인** — 전체 입력 정보 Review + 제출

**Acceptance Criteria:**
- [ ] 각 단계에서 필수 필드 미입력 시 "다음" 버튼 비활성화
- [ ] 날짜 필드에 min/max 유효성 검증 적용
- [ ] 주말 할인 금액은 숙박타입이 '평일전용'일 때 입력 불가 (자동 0 설정)
