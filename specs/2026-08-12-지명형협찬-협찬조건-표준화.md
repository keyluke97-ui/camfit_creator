> 선행 스펙: `specs/2026-08-11-지명형협찬-1a-v2-포트폴리오-재설계.md` (이하 "v2 스펙")

## 0. 한 줄

**협찬 조건을 크리에이터가 채워야 존재하는 것에서, 캠핏이 정해두고 다른 사람만 고치는 것으로 바꾼다.**

---

## 1. 왜

지명형은 **캠지기가 선입금한 뒤** 크리에이터를 만난다. 사전 정보가 곧 분쟁 예방선이다(v2 스펙 §1).

운영에서 걱정하는 분쟁은 네 갈래다 — **일정 불일치 · 산출물 시비 · 현장 조건 충돌 · 지표 부풀리기.**

| 갈래 | 이번 스펙 |
|---|---|
| 지표 부풀리기 | v2 전수 심사(D8)가 **이미 덮었다** |
| 산출물 시비 | §3 업로드 기한 · 산출물 표준 |
| 현장 조건 충돌 | §3 반려동물 · 드론 + §5 동반 인원 |
| **일정 불일치** | **이번에 다루지 않는다** — §2 폐기된 대안 참조 |

일정을 뺀 이유는 후보 셋(성수기 가능 여부 · 날짜 슬롯 · 최소 협의 리드타임)이 전부 근거가 부족하거나 1b 소관이었기 때문이다. 근거 없이 표준을 정하면 **그 표준이 새 분쟁 소스가 된다.** 일정은 실제 사례가 쌓인 뒤 별도로 다룬다.

동시에 제약이 하나 있다. v2 D7이 *"필수는 최소, 선택은 완성도 유인"* 이고, `프로필 공개=true`는 여전히 **0명**이다. 항목을 필수로 늘리면 리스트 밀도부터 확보가 안 된다.

두 요구는 정면으로 부딪히는 것처럼 보이지만, 부딪히는 이유는 **"조건이 존재한다"와 "크리에이터가 입력했다"를 같은 것으로 두었기 때문**이다. 둘을 분리하면 동시에 만족한다.

## 2. 확정 결정

| # | 결정 | 근거 |
|---|---|---|
| E1 | **표준 조건을 캠핏이 정하고, 다른 사람만 고친다(opt-out)** | 분쟁 예방의 본질은 "합의된 기준이 존재하는가"이지 "크리에이터가 입력했는가"가 아니다. 표준이 있으면 **아무것도 안 채운 사람에게서도** 분쟁이 안 난다. 마찰이 거의 0이라 D7과 충돌하지 않는다 |
| E2 | **표준값은 Airtable이 아니라 공유 상수에 둔다** | Airtable에 실제로 써넣으면 353명 백필이 필요하고, 표준을 바꿀 때마다 다시 백필해야 한다. 상수면 한 곳만 고치면 전원에 반영된다 |
| E3 | **표준으로 못 덮는 것은 `동반 인원` 하나뿐 — 공개 게이트 필수로 올린다** | 표준값은 *책임 소재 확정*은 해주지만 *현장이 안 터지는 것*은 못 한다. 2인용 사이트에 4명이 오면 누구 잘못인지 확정돼도 그날 밤은 이미 망한다. 사이트 정원은 물리적 제약이다. D7의 의도적 예외 |
| E4 | **업로드 기한 예외는 "더 길게"만 고르게 한다** | 크리에이터가 스스로 7일로 걸었다가 못 지키면 그게 곧 분쟁이고, 짧게 걸어 얻는 이득이 없다 |
| E5 | **산출물 편수에 예외 필드를 만들지 않는다** | 형식별 편수를 구조화하면 필드가 6개 는다. 캠지기는 금액을 못 바꾸므로(v2 D5) 크리에이터가 편수를 늘릴 유인이 없고, 줄이는 건 표준이 막는다. 더 주고 싶으면 기존 `콘텐츠 제작 기준` 자유 서술을 쓴다 |
| E6 | **`채널콘셉트`는 기존 필드를 열지 않고 `(자기신고)` 신규 필드로 받는다** | 353명 중 **170명(48%)** 에 운영자가 채운 값이 있다. v2 스펙 §9가 이미 같은 패턴을 두 번 금지했다(`채널 URL` 341/347 영업 데이터 / 기존 지표 필드) |
| E7 | **`채널콘셉트(자기신고)` 변경은 재검토 트리거에 넣지 않는다** | 지표가 틀리면 선입금 **금액**이 잘못 나가지만, 콘셉트는 매칭 필터라 틀려도 캠지기가 제안을 안 하거나 콘텐츠 링크를 보고 걸러낸다. 콘셉트 변경으로 재검토 큐를 채우면 **진짜 지표 변경이 그 안에 묻힌다.** 최초 전수 심사에는 당연히 포함 |

### 폐기된 대안

- **모든 조건을 크리에이터 입력 필드로 받는 안(A안)** — 입력이 8~10개 늘어 D7과 정면 충돌한다. 공개율 0명인 상태에서 필수를 늘리는 방향은 리스트 밀도를 더 누른다.
- **산출물은 1b 제안 화면에서 확정하는 안(C안)** — 1a 범위는 최소로 유지되나, 가장 큰 분쟁인 산출물 시비를 다음 단계로 미루게 된다. 선입금이 **1a 시점에** 일어나므로 미룰 수 없다.
- **성수기·연휴 방문 가능 여부** — 실제 분쟁 사례가 없어 항목 자체를 뺐다. 근거 없이 표준을 정하면 그 표준이 새 분쟁 소스가 된다.
- **`크리에이터 날짜 슬롯` 테이블 활용** — 테이블은 있으나 레코드 **0건**. 날짜 단위 슬롯은 현재 필요보다 과하다. 요일 + 제안 시점 기간 협의로 충분하다.
- **최소 협의 리드타임** — 제안 흐름의 문제라 1b 소관.
- **지표 증빙 스크린샷** — 전수 심사(v2 D8)가 이미 그 자리를 덮는다.

## 3. 표준 조건

| 표준 | 값 | 근거 | 예외 |
|---|---|---|---|
| **업로드 기한** | 체크아웃 후 **14일** | `tools/content-followup/overdue.cjs`의 `GRACE_DAYS = 14`. 미업로드 독촉 대상을 **이미 이 기준으로 뽑고 있다** — 새 숫자를 만들지 않고 운영이 쓰는 값을 승격 | 21일 / 30일 |
| **산출물** | 선택한 **콘텐츠 형식마다 1편** | `제작 콘텐츠 형식`이 이미 multipleSelects. 형식 3개를 골랐으면 3편으로 확정 | 없음 (E5) |
| **반려동물 동반** | 없음 | 명시돼 있으면 책임이 확정되고, 켠 사람은 애견동반 가능 캠핑장만 매칭하면 된다 | 체크로 켬 |
| **드론 촬영** | 없음 | 비행금지구역·캠핑장 허가 이슈. 켰을 때만 캠지기가 사전 확인 | 체크로 켬 |

**체크아웃 기준**은 `overdue.cjs`와 동일하게 **입실일 + 1박**으로 본다. 두 곳이 다른 날을 가리키면 독촉 도구와 화면 안내가 어긋난다.

## 4. 데이터 흐름

```
lib/constants.ts  ──(동일값 유지)──  camjigi shared-constants.js
      │                                    │
      ▼                                    ▼
포털 프로필 화면                      캠지기 카드 / 제안서
"표준 조건 적용 중"                   빈 값이면 표준을 렌더
      │
      ▼ (고친 것만)
크리에이터 명단 신규 필드 ── 예외값만 저장 (대다수는 빈 값)
      │
      ▼ (제안 확정 시점 — 1b/어드민, 이번 범위 아님)
지명 제안 `조건 스냅샷` ── 표준+예외 병합 문구를 텍스트로 박음
```

`조건 스냅샷`은 `지명 제안` 테이블에 **이미 존재하는 필드**다. 분쟁은 "지금 조건이 뭐냐"가 아니라 "제안 당시 조건이 뭐였냐"에서 나고, v2 §3.6 고지 문구가 이미 *"제안 시점의 조건으로 진행됩니다"* 로 약속하고 있다. 다만 v2 §9가 **"`지명 제안` 테이블에 포털이 쓰지 말 것"** 으로 못 박아 두었으므로 **이번 범위에서는 협의만 하고 구현하지 않는다.**

| `채널콘셉트(자기신고)` | multipleSelects | 운영자 `채널콘셉트` 폴백 | 옵션 12종을 **기존 필드와 똑같은 문자열**로 |

`채널콘셉트(자기신고)` 옵션 12종 — 기존 `채널콘셉트` 필드에서 그대로 복사한다. 두 값을 같은 자리에 렌더하므로 문자열이 어긋나면 안 된다:

```
캠핑 · 등산 · 여행 · 가족 · 커플 · 솔로 · 반려동물 · 차박 · 백패킹 · 장비리뷰 · 캠핑요리 · 낚시
```

**동반 인원 상한 10의 근거** — 캠핑 사이트 정원 현실. 그 이상은 단체라 별도 협의 대상이고, 상한이 없으면 오타(`999`)가 그대로 캠지기 카드에 뜬다.

export function buildDeliverableSummary(

## 7. 캠지기측 협의 항목

| # | 내용 | 안 되면 |
|---|---|---|
| 1 | **빈 값이면 표준을 렌더** — `업로드 기한(일)`이 비었으면 "체크아웃 후 14일"로 표시 | **B안 전체가 무너진다.** 지금 고치려는 "카드가 빈다"가 그대로 남는다 |
| 2 | 신규 필드 5개 생성 (§5) | 읽기는 `undefined`, 쓰기는 422 |
| 3 | `채널콘셉트(자기신고)` 우선 · 없으면 `채널콘셉트` 폴백으로 렌더 | 170명(48%)의 기존 분류가 카드에 안 뜬다 |
| 4 | `조건 스냅샷`을 **누가 언제 쓰나** — 어드민 자동화인지 1b 포털인지 | 제안 시점 조건이 안 남아 분쟁 때 "그때 뭐라고 했냐"를 못 가린다 |
| 5 | 제안서(`제안서 전문`·`채널 패키지`)에 산출물 표준 문구 반영 | 캠지기가 받는 문서와 포털 표시가 어긋난다 |

## 9. 하지 말 것

- **기존 `채널콘셉트`(운영자 필드)에 쓰지 말 것** — 170명 분류가 지워진다. 자기신고는 신규 필드로만 (E6)
- **표준값을 Airtable 필드에 백필하지 말 것** — E2의 전제가 깨진다. 빈 값이 곧 "표준 적용 중"이어야 한다
- **`업로드 기한(일)`에 14를 저장하지 말 것** — 표준과 같은 값이면 `null`로 클리어한다. 14가 저장돼 있으면 나중에 표준을 15로 바꿔도 그 사람만 14로 남는다
- **`지명 제안` 테이블에 포털이 쓰지 말 것** (v2 §9 유지)
- **필드명·옵션 문자열 임의 변경 금지** — Airtable은 없는 필드에 써도 에러를 안 내는 경우가 있어 무증상 실패가 난다
- **`채널콘셉트(자기신고)`를 재검토 트리거에 넣지 말 것** — 진짜 지표 변경이 큐에서 묻힌다 (E7)
