## 1. 배경 & 정책 컨텍스트

### 1.1 A′안 요약 (선입금 + 조건부 자동수락)
크리에이터가 프로필에 **협찬 수락 조건(지역·요일·사이트유형·최소단가)** 을 미리 걸고 **프로필 공개**하면, 캠지기가 그 조건에 맞는 제안을 하며 **선입금**할 때 크리에이터의 개별 수락 없이 **자동 확정**되는 구조(에어비앤비 인스턴트 북 + 조건 필터 모델).

- 통제권 = "개별 수락/거절"이 아니라 **"사전 조건 + 가격"**. 원치 않으면 단가를 높이거나 조건을 좁힌다.
- 옵트인 = **2단 플래그(Airbnb식, 2026-07-16 확정)**: **`프로필 공개` ON** → 캠지기 리스트 노출·제안 수신(가시성). **`자동수락 활성` ON**(별도) → 조건 맞는 선입금 제안이 개별 승인 없이 **자동 확정**(인스턴트북). **공개는 하되 자동수락은 끌 수 있다.**
- 안전판 = 확정 후 **제한적 예외 거부권**(1b 범위).

### 1.2 안B(폐기) 대비 포털이 바뀐 점
원래 SDD v3 빌드 스펙의 핵심이던 **"제안 수신함 = 수락/거절 인박스 + 수락 마감 카운트다운"** 은 A′ 자동수락으로 **폐기**된다. 대신 포털의 핵심은 **"크리에이터가 조건을 걸고 공개하는 포트폴리오"** 로 이동한다.

### 1.3 이 문서(1a)의 위치
지명형 포털 작업을 두 덩어리로 분할한다.
- **1a (본 문서)** — 포트폴리오 + 협찬 조건 + 정산 온보딩. **선입금 법무 게이트와 무관 → 지금 착수 가능.**
- **1b (후속)** — 확정 협찬 뷰 + 예외 거부권. **선입금 법무 클리어 + 지명 제안 `상태` 옵션 A′ 갱신 후 착수.**

법무(전자금융거래법 예치금 이슈 재확인)는 병렬 진행 중이며, 1a는 법무 대상(선입금 수납·예치·환불)을 건드리지 않으므로 게이트에 막히지 않는다.

## 3. 사용자 플로우 (크리에이터 관점)

1. 로그인(기존 `/login`, `auth-token` JWT 재사용)
2. 대시보드에서 "내 협찬 프로필" 배너 → `/dashboard/portfolio` 진입
3. **포트폴리오** 작성 — 프로필 이미지 업로드 + 대표 콘텐츠 링크
4. **협찬 수락 조건** 설정 — 기준 지역 확인 → 방문 가능 지역(기본가) → 원정 제안(유류비 +10만) → 방문 요일, 수용 사이트 종류, 최소 협찬 단가 (§6.4)
5. **정산 정보** — 기존 프리미엄 등록자면 정산정보 불러와 확인 / 미등록자면 프리미엄 협찬 등록으로 유도
6. **`프로필 공개` 토글 ON** 시도 → 필수 항목 체크 → 미완이면 안내 후 차단 / 완성이면 공개(리스트 노출)
7. (선택) **`자동수락 활성` 토글 ON** 시도 → **자동수락 동의 모달** → 동의 시 인스턴트북 활성. 끄면 공개는 유지되나 자동확정 안 됨
8. 공개+자동수락 시 캠지기 리스트에 노출되고, 조건에 맞는 선입금 제안이 자동 확정된다(이후 흐름은 1b·포털 밖)

## 4. 화면 설계

- **라우트**: `/dashboard/portfolio` — middleware `matcher: ['/dashboard/:path*', ...]` 로 자동 인증 보호(추가 작업 없음).
- **구조**: 단일 스크롤 편집 페이지, **섹션형**. 모바일 퍼스트 `max-w-md`. 기존 `PremiumRegisterForm`의 `SectionTitle`·`FormInput` 하위 컴포넌트 패턴과 라이트 테마 토큰(§디자인시스템) 재사용.
- **진입점**: 대시보드 메인(`app/dashboard/page.tsx`)에 "내 협찬 프로필" 진입 배너 추가(기존 `ContentEntryBanner` 패턴 참고).

### 섹션 1 — 포트폴리오 (캠지기가 보는 것)
- **프로필 이미지** (필수) — 파일 업로드 → Airtable `uploadAttachment`. 클라이언트에서 리사이즈 후 전송(≤5MB).
- **대표 콘텐츠 링크** — URL 입력. `target="_blank" rel="noopener noreferrer"` 규칙 유지.
- **(읽기 전용 표시)** 채널명 · 등급 뱃지(⭐×N) · 팔로워 구간 — 크리에이터 명단 기존 필드에서 읽어 표시만. 운영자 관리 영역이라 편집 불가.

### 섹션 2 — 협찬 수락 조건 (A′ 필터)
지역·가격은 **2단 순차 입력**(상세 §6.4):
- **기준 지역** (신설 `기준 지역`) — 정산 `주소`에서 시/도 프리필 + 크리에이터 확인/수정. 원정 후보 산출 기준.
- **1차 · 방문 가능 지역** (`방문 가능 지역`) — "기본가로 갈 수 있는 지역" 9권역 멀티선택.
- **2차 · 원정 제안** (신설 `원정 가능 지역`) — 기준 지역의 원정 후보(§6.4 맵) 중 1차 미선택 지역만 노출: 지역별 *"🚗 유류비(+10만) 받으면 여기도 가실 수 있나요? [예/아니오]"*. 예 → `원정 가능 지역` 추가 + 안내문("이 지역은 캠지기가 유류비 10만 원 얹어 제안하면, 자동수락 켜져 있을 때 개별 승인 없이 자동확정됩니다").
- **방문 가능 요일** — 7일 멀티선택
- **수용 사이트 종류** (`fldWmvzbNngsSoNrZ` — ops 기생성, 실측 확인) — 8종 멀티선택
- **최소 협찬 단가** — 기존 `협찬 희망 금액` 필드 재사용. "이 금액 이상 제안만 받아요" 카피. (원정 지역엔 +유류비 10만이 자동 가산 — §6.4)
- 안내문: "조건에 맞는 제안만 도착하고, (자동수락 ON 시) 캠지기가 선입금하면 개별 승인 없이 자동 확정됩니다."

### 섹션 3 — 정산 정보
- **premiumId 있음** → 기존 정산정보 **마스킹 표시**(은행 + 계좌번호 뒤 4자리 + 예금주) + [이 정산정보로 진행] 확인 버튼. 수정 원하면 프리미엄 재등록 안내.
- **premiumId 없음** → "정산 정보 등록 필요" 안내 + [프리미엄 협찬 등록하기] → `/premium-register`.

### 섹션 4 — 공개 (2단 옵트인: 프로필 공개 + 자동수락 활성)
2단 토글. **`자동수락 활성`은 `프로필 공개`의 하위 옵션**(공개 OFF면 자동수락도 의미 없음 → 비활성/동기 OFF).

**① `프로필 공개` 토글** (가시성)
- ON 시도 시 → **§5 필수 완성 항목 검증** → 미완이면 빠진 항목을 명시하고 토글 차단.
- 완성 시 ON → 캠지기 리스트 노출·제안 수신. 이미 공개된 상태에서 OFF는 자유(제약 없음). OFF 시 `자동수락 활성`도 함께 OFF.

**② `자동수락 활성` 토글** (인스턴트북 — 별도 옵트인)
- `프로필 공개` ON 상태에서만 조작 가능(공개 OFF면 disabled).
- ON 시도 시 → **자동수락 동의 모달**: "조건(지역·요일·사이트유형·최소단가)에 맞는 캠지기가 선입금할 때 개별 승인 없이 **자동 확정**됩니다. 원치 않으면 조건을 좁히거나 이 토글을 끄세요." + [동의하고 자동수락 켜기].
- OFF면 공개는 유지되나 자동확정 안 됨(제안은 받되 개별 처리는 1b 범위).

## 5. 공개(발행) 게이팅 — 필수 완성 항목

`프로필 공개` ON을 허용하는 조건(전부 충족해야 함):

- [ ] **프로필 이미지** ≥ 1장
- [ ] **대표 콘텐츠 링크** 입력됨(유효 URL)
- [ ] **방문 가능 지역** ≥ 1개
- [ ] **방문 가능 요일** ≥ 1개
- [ ] **수용 사이트 종류** ≥ 1개
- [ ] **최소 협찬 단가** > 0
- [ ] **정산 정보 존재**(premiumId 있음)

미완 시 토글은 비활성 + 무엇이 빠졌는지 체크리스트로 안내. 검증은 **서버(PATCH 시)에서도** 재확인하여 클라이언트 우회 차단.

**`자동수락 활성` ON 조건**: `프로필 공개`가 이미 ON(=위 항목 전부 충족)일 것 + 자동수락 동의. 서버 PATCH에서 `자동수락 활성=true`면 `프로필 공개=true`도 함께여야 통과(아니면 400). `프로필 공개=false`로 내리는 PATCH는 `자동수락 활성`도 강제 false로 동기화.

### 6.4 지역·가격 모델 — 원정 인센티브 (2026-07-16 확정)

**배경/목표**: 경상·전라는 프협에서도 매칭률이 낮고 로컬 크리에이터 수가 적다. 해법 = **수도권 크리에이터를 원정 인센티브(유류비)로 끌어온다.** "먼 지역은 유류비 얹으면 간다"를 크리에이터가 사전 선언하게 하고, 캠지기가 그 값 이상 제안하면 자동수락으로 매칭.

**3개 상태(지역별)**:
- **기본가** — `방문 가능 지역`에 있으면 `협찬 희망 금액`(기본 단가)으로 수락.
- **원정(+유류비)** — `원정 가능 지역`에 있으면 `협찬 희망 금액 + 유류비(10만)`으로 수락.
- **불가** — 둘 다 아니면 매칭 안 됨.
- `방문 가능 지역` ∩ `원정 가능 지역` = ∅ (**상호배타**. 한 지역은 기본가 아니면 원정, 둘 다 불가).

**유류비 = 플랫폼 고정 상수 `WONJEONG_SURCHARGE = 100000`** (크리에이터가 못 만짐 — 금액 부풀리기 어뷰징 차단). UI 라벨은 "유류비". 코드 상수(`lib/constants.ts`), **camfit-premium과 공유(동일 값 하드코딩 + 계약 문서화)**. v1 단일값의 한계는 §15.

**어뷰징 차단(개인화 + 근거리 프리미엄 방지)**: "원정"은 지역 고정이 아니라 **크리에이터 기준 지역 상대**다(충남 사람에게 전라는 근거리, 경기 사람에게는 원정). 그래서 **`원정 가능 지역`으로 켤 수 있는 후보 = `WONJEONG_MAP[기준 지역]`으로 제한**한다. 근거리 지역(예: 충남→전북)은 후보에 안 떠서 유류비를 못 붙인다.

**`WONJEONG_MAP` (기준 지역 → 원정 후보) — 초안. △=경계(2.5~3h), 운영 판단으로 상수 한 줄 조정 가능. 좌우 대칭.**

|---|---|---|
| 경기도(서울, 인천 포함) | 전라북도△·전라남도·경상북도·경상남도 | 경기·강원·충북·충남 |

**camfit-premium 계약(포털 밖, 매칭 검증)**: 제안 지역 R에 대해 `필요단가(R) = 협찬 희망 금액 + (R ∈ 원정 가능 지역 ? 100000 : 0)`. `조건 부합 여부 = ( R ∈ 방문가능 ∪ 원정가능 ) AND (제안액 ≥ 필요단가(R)) AND (요일·사이트유형 일치)`. 캠지기 화면은 지역 선택 시 `필요단가(R)`(기본가 or +10만)를 노출. → **두 레포가 `WONJEONG_MAP`·`WONJEONG_SURCHARGE`·필드명·옵션값을 일치**시켜야 함(§12 P2).

**동의 처리**: 원정 지역별 "예" = 그 지역 원정 자동수락 동의(별도 모달 없음, 인라인 안내문). 단 실제 자동확정은 마스터 `자동수락 활성` ON일 때만(§4 섹션4). `자동수락 활성` OFF면 원정 제안도 수동(1b).

## 8. 이미지 업로드 (Airtable `uploadAttachment`)

- **필드는 이미 존재**(`프로필 이미지`). 필요한 건 브라우저 → 첨부 필드 업로드 경로.
- **방식**: `POST https://content.airtable.com/v0/{baseId}/{creatorId}/{프로필 이미지 fieldIdOrName}/uploadAttachment` — body `{ contentType, filename, file(base64) }`. **외부 호스트(AWS/Blob) 불필요.**
- **제약**: 파일당 ≤ 5MB → 클라이언트에서 리사이즈/압축 후 base64 전송.
- **소유권**: 항상 JWT `creatorId` 레코드에만 업로드(본인 것). body로 record id 받지 않음.
- **표시**: Airtable 첨부 URL은 만료성 → 레코드 읽을 때마다 서버에서 fresh URL 취득해 노출. 캐싱/영구 저장하지 않음.
- **검증 포인트**: 구현 시 Airtable `uploadAttachment` 엔드포인트 스펙(엔드포인트 경로·필드명 허용 여부·용량) 최신 문서로 확인.

## 10. 에러 처리

- API 라우트: try-catch → `NextResponse.json({error: '...'}, {status: 4xx/5xx})`. 500 에러 메시지는 기존 톤(“…잠시 후 다시 시도해주세요. 계속되면 카카오톡 채널로 문의해주세요.”) 통일.
- lib 함수: try-catch 내 `console.error` — 조회 함수는 null 반환, 쓰기 함수는 throw. catch에서 에러 삼키지 않음.
- 이미지: 용량 초과·포맷 오류 → 사용자 친화 메시지.
- 저장 실패 → 낙관적 UI 롤백(기존 `handleNotificationToggle` 패턴 참고).

## 15. 미결 / 리스크

- **[하드게이트, 병렬]** 선입금 예치 법무·세무(전자금융거래법) — 1a는 무관하나 1b·포털 밖 선입금 흐름의 전제.
- **예외 거부권 수치**(1b) — 횟수·기간·페널티 미정. 확정뷰 UI 전에 필요.
- **확정 후 패시브 노쇼** 처리 규정 — A′ 문서 공백(능동 예외거부만 정의). 포털 밖이나 정책 확정 필요.
